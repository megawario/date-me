Make it yours.

A beginner-friendly guide

Make a card that starts a conversation.

This site is a small, playful template: put your own personality into it, publish it for free with GitHub Pages, and link to it from a physical card. You do not need to know how to code to change the words and pictures.

Start the guide ↓ Open the project ↗

Before you start

Gather a few things.

  • A free GitHub account and a web browser.
  • Your own photos, words, and links. The example images in this project are protected, so do not publish them in your version.
  • A public address you want the card’s QR code to open. This will be your GitHub Pages address once the site is published.
  • Optional: a Spotify track, album, or artist you would like to include.

Use images you can share

Replace every file in assets/images/ before publishing your fork. Use photos you took, made, or have permission to use. The included image files are not part of the MIT license.

The setup

From fork to first card.

  1. Fork the project

    Open the Date-a-Mario repository, select Fork near the top right, then choose your own account as the destination. GitHub creates a personal copy that you can safely edit.

  2. Learn where things live

    On your fork, select a filename to open it and use the pencil icon to edit it in the browser. The main files you will use are index.html for the landing page, data/profiles.js for profile cards, data/card.js for the printable card, and assets/images/ for pictures.

  3. Replace the sample pictures

    Open the assets/images folder and upload your replacements. Keep the filenames, or update every matching image path in data/profiles.js and data/card.js. You can also delete image cards you do not want.

  4. Make the landing page sound like you

    Open index.html and edit the visible text in the hero, “How it works,” and “Why this exists” sections. Change the preview image path and any links that should point to your own accounts or pages. Save with a short message such as “Personalize landing page.”

  5. Build your profile sequence

    Open data/profiles.js. Each item in profiles is one version of you, and its cards appear from top to bottom before a visitor chooses left or right. Keep the punctuation, quotation marks, brackets, and commas intact: a missing comma can stop the configuration from loading.

  6. Configure and print the physical card

    In data/card.js, set destinationUrl to your full published site address and displayUrl to the shorter address you want printed. Then open card.html, choose “Print card,” use 100% or actual-size scaling, and turn off browser headers and footers.

  7. Turn on GitHub Pages

    In your fork, open Settings, then Pages. Under “Build and deployment,” choose Deploy from a branch, select main and the /(root) folder, then save. GitHub will show the public address when the deployment is ready.

Profiles and cards

Choose what someone gets to see.

A profile needs an id, name, accentColor, and a list of cards. Set shuffleProfiles to true if you want the profiles in a different order on each visit, or false to preserve your chosen order.

{
  "shuffleProfiles": false,
  "profiles": [{
    "id": "weekend-me",
    "name": "Weekend Me",
    "accentColor": "#d7cbe5",
    "cards": []
  }]
}

Available card types

The “Scroll for more ↓” and “Left or right?” footer cue is shared by every card. Keep it unchanged when customizing card copy or imagery.

profile
Your introduction: name, age, catchphrase, tags, and optionally an image.
text
A full card for a story, thought, or invitation.
image-text
A photo with one short bottom caption, kept small so the photo stays visible. It does not change the “Scroll for more ↓” cue.
image-text-fade
A text card with an image behind it. Hold to swipe and the text fades away to reveal the image.
image
A photo-only moment; always write a useful imageAlt description.
spotify
An embedded Spotify track, album, or artist. Use an https://open.spotify.com/embed/ URL and an accessible title.

A small Spotify example

Spotify’s Share menu can provide an embed link. Use the version beginning with https://open.spotify.com/embed/; regular Spotify links will not work here.

{
  "type": "spotify",
  "title": "A song I keep replaying",
  "embedUrl": "https://open.spotify.com/embed/track/…"
}

Check and publish

See your work before sharing it.

Preview on your computer

The landing page can be opened by double-clicking index.html. To reliably preview the profiles and printable card, serve the folder with a simple local web server; browsers often block their configuration files when opened directly from your computer. If that sounds unfamiliar, publish with GitHub Pages first and use the public address as your preview.

Publish later changes

Whenever you edit a file in GitHub and choose Commit changes, GitHub Pages automatically publishes the update. It can take a few minutes. Reload the page after a short wait, then test the profile flow and scan the card’s QR code before you print a batch.

Common snags

The page is not online yet
Check Settings → Pages. Confirm the source is the main branch and /(root), then allow a few minutes for the first deployment.
Pictures are missing
Check the spelling and capitalization of the filename and path. GitHub Pages treats Photo.jpg and photo.jpg as different files.
The profiles page says it cannot load
Review the most recent edit to data/profiles.js. Look especially for a missing comma, quotation mark, or closing bracket.
The QR code goes to the wrong place
Update destinationUrl in data/card.js with the complete public URL, save it, and reopen card.html before printing again.
